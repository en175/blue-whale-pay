# ADR-0001：支付建设阶段开启与 `blue_whale_pay_server` 技术栈归宿

- **状态**：已接受
- **日期**：2026-09-20
- **决策者**：lixq
- **关联**：兄弟仓 `blue-whale-ai` [ADR-0055](../../../blue-whale-ai/docs/adr/0055-prelaunch-typescript-unification-scope.md)（上线前 TypeScript 统一的范围边界）
- **触发**：杭州银行（易码付）渠道接入需求

## 背景

本仓 `blue_whale_pay_server/` 自 2026-08-04 起处于冻结状态（见 `FROZEN.md`），依据是兄弟仓 ADR-0055：

> 仓库中尚未落地的 `blue-whale-pay`、Node Payment Gateway、微信/支付宝渠道接入……**它们是未来支付功能**……**待产品真正进入支付建设阶段后另行设计和实施**。

`FROZEN.md` 同时规定：「**AI Agent 执行实现任务时，不得在本目录写入**」，并明确「支付建设阶段开始时**另行决策其技术栈归宿**」。

2026-09-20，业务方提出接入杭州银行（易码付）收单渠道，需完成支付、退款、查询、异步通知、轮询五项能力。这**正是 ADR-0055 所指的「渠道接入」**，即冻结条款所等待的触发条件。

## 决策

1. **支付建设阶段于 2026-09-20 开启**，`blue_whale_pay_server/` 冻结解除，允许新增与修改代码。

2. **技术栈归宿为 Java `blue_whale_pay_server`**，不新建 Node/TS 支付网关。理由见下。

3. **首个接入渠道为杭州银行（ifCode = `hccb`）**，走杭州银行线上支付平台 `ifsp-payweb/SOA/txnAccept` 接口。

4. **架构沿用本仓既有渠道模式**：`IPaymentService` / `IRefundService` / `IPayOrderQueryService` / `IChannelNoticeService` 四接口 + Spring Bean 名约定（`<ifCode> + 后缀`）+ `payway/` 按 wayCode 反射分派。不引入新的抽象层。

5. **轮询复用现有定时任务** `PayOrderReissueTask` / `RefundOrderReissueTask`（cron 每分钟），不新增调度器。

## 理由（方案取舍）

候选三方案：

- **沿用 Java `blue_whale_pay_server`（采纳）**
  该仓已完整实现 Jeepay 的六渠道骨架（alipay / wxpay / ysfpay / xxpay / pppay / plspay）、订单状态机、补单轮询、商户通知、对账基础。杭州银行只需按既有模式新增一个 `ifCode`，改动面收敛在 `channel/hccb/` 一个包内。团队母语为 Java（兄弟仓 ADR-0084 的同一判据）。代价：违反兄弟仓 CLAUDE.md 红线 #10「禁止新增 Java 产品运行时」——但该红线约束的是**产品实现**，且 ADR-0055 已为支付单列豁免路径（「另行决策」），本 ADR 即为该决策。

- **新建 Node/TS 支付网关**
  ADR-0055 提到过「Node Payment Gateway」，但该处代码尚不存在，等于从零搭建渠道骨架、订单状态机、补单机制、对账——而这些在 Java 侧都已可用。成本与风险显著更高。

- **维持冻结、仅出方案文档**
  无法推进业务需求，且 ADR-0055 的等待条件已经满足，继续冻结失去依据。

选 1：以**已有可运行实现**为锚，避免重复建设。

## 后果

**正向**
- 杭州银行渠道可在既有骨架上增量实现，改动面小、风险可控
- 订单状态机、补单轮询、商户通知、幂等与对账能力全部复用，无需重新验证
- 兄弟仓 `blue-whale-api`（new-api）**零代码改动**：渠道对其透明，仅需管理后台配置

**成本与风险**
- 需在本仓引入 CFCA `SADK.jar` + `cfca.jar`（不在 Maven 中央仓库），打包可复现性需处理
- 杭州银行是**首个银行类渠道**，其「上传 pfx 证书 + 密码」的配置模式与现有六渠道（SDK / API Key）不同，证书存储链路需验证
- 供应商接口文档（V0.14）与实际报文存在多处偏差（见方案文档），实现以**实测报文**为准，文档仅作参考
- 兄弟仓 CLAUDE.md 红线 #10 的表述需同步修订，否则规则文本与本 ADR 冲突

**约束**
- 本决策只开启 `blue_whale_pay_server/`，不改动兄弟仓任何产品代码
- 后续若渠道接入数量或复杂度显著上升，应重开本 ADR 重新评估归宿
