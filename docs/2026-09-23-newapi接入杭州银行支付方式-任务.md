# 任务：new-api 接入「杭州银行聚合主扫」支付方式

- **目标仓库**：`blue-whale-api`（new-api，Go）— `git@gitee.com:hangzhou_xuanfu_1/blue-whale-api.git`
- **上游仓库**：`blue-whale-pay`（Java 支付网关）— 杭州银行渠道已接入完成
- **日期**：2026-09-23
- **前置**：上游 `blue-whale-pay` 的 hccb 渠道已开发完成并部署测试环境验证通过（含真实异步回调）

---

## 1. 背景

上游 `blue-whale-pay` 新增了**杭州银行（hccb）聚合主扫**渠道。

**关键特性：不区分支付宝/微信。**

银行返回的是**统一收银台链接**，用户扫码后在**银行的页面上**自选微信/支付宝/云闪付。商户下单时不需要、也拿不到渠道信息。

因此 new-api 侧**只需要一个支付方式**，不再需要区分支付宝/微信。

**目前 new-api 已有**：经 blue-whale-pay 的支付宝直连（`ALI_QR`）、微信直连（`WX_NATIVE`）两条通道。

---

## 2. 与上游的契约（已实测）

### 2.1 下单

```
POST {BlueWhalePayPayUrl}/api/pay/unifiedOrder
参数：mchNo, appId, mchOrderNo, wayCode, amount(分), currency, clientIp,
      subject, body, notifyUrl, reqTime, version=1.0, signType=MD5, sign
```

**新增的 wayCode：`HCCB_QR`**

### 2.2 响应

```json
{
  "code": 0, "msg": "SUCCESS",
  "data": {
    "payOrderId": "P2102290508813254658",
    "orderState": 1,
    "payDataType": "codeUrl",
    "payData": "https://test.hccb.cc:10444/.../uniCashierNew.html?tokenCode=xxx&uniCashierPayType=null"
  }
}
```

`payData` 是**收银台链接**，前端转成二维码给用户扫即可。

### 2.3 回调

上游回调 new-api 的 `/api/bluewhalepay/notify`（GET + query + sign），new-api 验签后返回 `"success"`。

**现有回调逻辑无需改动**——回调体里带 `ifCode`（本次为 `hccb`）、`wayCode`、`state` 等。

## 3. 需要改的地方

### 3.1 ⚠️ 必改：档位充值的支付方式硬校验

**`controller/recharge.go:46`**

```go
if req.PaymentMethod != "wechat" && req.PaymentMethod != "alipay" {
    common.ApiErrorMsg(c, "支付方式仅支持 wechat / alipay")
    return
}
```

**这行会直接拒掉杭州银行。** 必须放开，并加上新方式的 wayCode 映射。

同文件 `:75-79` 的 wayCode 推导也要加分支：

```go
// wayCode：前端 wechat/alipay → WX_NATIVE(扫码) / ALI_QR
wayCode := "WX_NATIVE"
if req.PaymentMethod == "alipay" {
    wayCode = "ALI_QR"
}
```

→ 需要新增 `PaymentMethod == "hccb"`（或你定的值）→ `wayCode = "HCCB_QR"`。

> 档位充值把 `payment_method` 存**前端传的中文/英文枚举**（`wechat`/`alipay`），与钱包流存渠道族值（`wxpay`/`alipay`）不一致 —— 这是既有差异，本次按现约定新增第三个值即可。

### 3.2 必改：管理后台可选的支付方式

**`web/default/src/features/system-settings/integrations/payment-method-dialog.tsx:74-75, 116-124`**

现有两个选项：
```ts
bluewhalepay_alipay: 'SiAlipay',
bluewhalepay_wechat: 'SiWechat',
```

需要新增 `bluewhalepay_hccb_qr`（命名可自定，但要与 `:201-212` 的推导规则匹配）：

```ts
// web/default/src/features/wallet/index.tsx:204-212 —— 现有推导规则
blueWhaleChannel = type.replace('bluewhalepay_', '')
wayCode = channel === 'alipay' ? 'ALI_QR'
        : channel === 'wechat' ? 'WX_NATIVE'
        : channel.toUpperCase()          // ← 兜底：后缀直接大写
```

配 `type = bluewhalepay_hccb_qr` → 推导出 `HCCB_QR` ✅ **前端推导逻辑本身不用改**。

### 3.3 必改：钱包页的支付方式列表

支付方式列表由**管理后台配置**驱动（`PayMethods` 设置，见「常规 → 支付方式」）。

**操作**：
- 新增 `bluewhalepay_hccb_qr`
- 是否保留 `bluewhalepay_alipay` / `bluewhalepay_wechat` 由产品决定（见 §4）

### 3.4 需确认：`PaymentMethodFromWayCode` 的兜底

**`model/topup.go:42-51`**

```go
func PaymentMethodFromWayCode(wayCode string) string {
    switch {
    case strings.HasPrefix(wayCode, "WX_"):   return PaymentMethodWxPay
    case strings.HasPrefix(wayCode, "ALI_"):  return PaymentMethodAlipay
    default:                                   return PaymentMethodBlueWhalePay
    }
}
```

`HCCB_QR` 不匹配 WX_/ALI_ 前缀 → 落 **`bluewhalepay`** 兜底。

**这正好是「不区分」该有的值**，无需改代码。

⚠️ 但要确认展示层对 `payment_method = bluewhalepay` 有中文映射（存量记录里已有该值，应已支持）。

### 3.5 可选：二维码弹窗的图标与文案

**`web/default/src/features/wallet/components/recharge-form-card.tsx:517-534`**

现在只认 `ALI_QR`（支付宝图标+"请使用支付宝扫描"）和 `WX_JSAPI`/`WX_NATIVE`（微信），其他走 else 分支显示「扫码支付」。

`HCCB_QR` 会落到 else 分支 → **能正常显示**，但图标是默认的。可选加一个分支美化。

### 3.6 可选：默认 wayCode

**`setting/payment_bluewhalepay.go:12`**

```go
var BlueWhalePayWayCode = "ALI_QR"  // 默认支付方式（fallback）
```

若前端未传 wayCode 时想默认走杭州银行，改成 `HCCB_QR`。该值可在管理后台覆盖。

## 4. ⚠️ 需要产品决策的点

**杭州银行上线后，原有的「支付宝/微信」两个选项怎么处理？**

| 选项 | 影响 |
| --- | --- |
| **A. 保留三个选项**（支付宝 / 微信 / 杭州银行） | 用户可选择走哪条通道；`payment_method` 三种值共存 |
| **B. 用杭州银行替换掉两个**（只留一个「扫码支付」） | `payment_method` 新记录统一落 `bluewhalepay`；**存量记录仍是 `alipay`/`wxpay`，新旧混值**（展示层需能兼容） |

上游的 `blue-whale-pay` 是按 A 设计的（hccb 是新增渠道，不删原有通道），最终由产品定。

## 5. 验证步骤

1. **管理后台配支付方式**：加上 `bluewhalepay_hccb_qr`
2. **确认在 blue-whale-pay 侧已配好通道**：测试商户的应用需配 `HCCB_QR` → `if_code=hccb` 的支付通道，否则下单会报「无此支付通道接口」
3. **下单**：钱包充值或档位充值选杭州银行 → 应返回收银台链接并渲染二维码
4. **付款**：扫码后用微信/支付宝/云闪付完成支付
5. **验证回调**：new-api 应收到 `/api/bluewhalepay/notify` 并加额度
6. **验证兜底**：付款后查 `top_ups.payment_method`，应为 `bluewhalepay`
