实测响应中的 `tokenCodeURL` 指向 `uniCashierNew.html`，抓取该页面确认是**渠道选择页**：

- 渠道侧**只有一个 payway 类**

### 5.2 响应（成功）

```json
{
  "respCode": "0000",
  "respMsg": "交易成功",
  "respTxnSsn": "82026092010104934477806665402766",
  "respTxnTime": "20260920101049",
  "txnTokenPayData": "{...}",   // ⚠️ 实测是 JSON 字符串，非嵌套对象
    "tokenCode": "D05771D9B6F64C02810131EECAC6C890",
    "tokenType": "01",
    "tokenBegin": "20260920101049",
    "tokenEnd": "20260920104049",
    "tokenCodeURL": "https://test.hccb.cc:10444/ifsp-payweb/mobile/uniCashier/uniCashierNew.html?tokenCode=...&uniCashierPayType=null"
```

**要点**：

| 字段 | 说明 |
| --- | --- |
| `respTxnSsn` | 平台流水号，**退款必需**（`origRespTxnSsn`） |
| `respTxnTime` | 平台受理时间，**退款必需**（`origRespTxnTime`） |
| `txnTokenPayData.tokenCodeURL` | 出码内容（生成二维码给用户扫） |
| `tokenBegin` ~ `tokenEnd` | 令牌有效期，**30 分钟** |
| `txnTokenPayData` | ⚠️ 文档写的是 `respData` + `codeUrl`/`prepayId`，**实际字段名不同** |

### 5.3 查询（`1009/100900`）

请求：`merId`、`txnOrderId`（查询流水号）、`txnOrderTime`、`origTxnOrderId`（被查订单号）

响应：

```json
{
  "respCode": "0000",
  "respMsg": "查询交易成功",
  "orderStat": "10",
  "origRespCode": "3201",
  "origRespMsg": "该订单尚未支付,请稍候查询",
  "txnOrderId": "ORDER1789870249959"
}
```

**`orderStat` 判定表**：

| 值 | 含义 |
| --- | --- |
| `00` | 交易成功 |
| `01` | 交易成功（已发生退货/撤销） |
| `99` | 交易失败 |
| `09` | 交易已关闭 |
| 其他（实测 `10`） | **中间态**（未支付/支付中）→ 继续轮询 |

⚠️ 响应里的 `txnOrderId` 是**被查询的原订单号**，不是查询请求里的流水号。

⚠️ `origRespCode=3201`（该订单尚未支付）**不在文档附录 B 中**，属未收录码。

### 5.4 退款（`1008/100800`）

请求：

```json
{
  "txnType": "1008",
  "txnSubType": "100800",
  "merId": "8202608105388480",
  "txnOrderId": "{退款单号}",
  "txnOrderTime": "yyyyMMddHHmmss",
  "origTxnOrderId": "{原商户订单号}",
  "origRespTxnSsn": "{原平台流水号}",
  "origRespTxnTime": "{原平台受理时间}",
  "txnAmt": "1",
  "txnCcyType": "156"
}
```

实测响应（订单未支付）：`{"respCode":"1025","respMsg":"交易受理失败，原始平台流水号不存在"}`

→ **报文格式、字段名、加签全部正确**，银行正常受理（`1025` = 查无此交易）。

> ⚠️ **`origRespTxnSsn` + `origRespTxnTime` 必须持久化。** 二者来自下单应答或异步通知，Jeepay 现有 `PayOrder` 只存 `channelOrderId`，**不够用，需扩展**。

## 6. 签名与验签

### 加签（`EncryptUtil.sign`）

1. 排除 `signAture` 字段
2. 按参数名 **ASCII 升序**排序
3. 拼接 `key1=value1&key2=value2&...`（无末尾 `&`）
4. UTF-8 转字节
5. 私钥 **PKCS7 Detach 签名**（算法 `MechanismKit.SHA256`）
6. Base64 编码 → `signAture`

### 验签

1. 取响应 Map，排除 `signAture`
2. ASCII 排序拼接
3. `certDetachVerify(data, Base64.decode(signAture))`

> ⚠️ **银行文档明确要求「由于字段可能会增加，请勿在验签时写死」** —— 必须按收到的全部字段参与，不能固定字段列表。

### ⚠️ Demo 中已发现的缺陷（实现时必须修正）

| # | 缺陷 | 位置 | 后果 |
| --- | --- | --- | --- |
| 1 | 加签排除 `signature`/`attach`/`sign`，验签排除 `signAture` —— **两端不一致** | `EncryptUtil.java:61` vs `MapUtils.java:38` | 签名字段不统一，须**统一排除 `signAture`** |
| 2 | 证书异常时返回 `map.toString()`（`{msg=证书报错, code=99}`）冒充签名值 | `EncryptUtil.java:93-94` | 报错被当签名发出、下游静默失败，须**抛异常** |
| 3 | `pfx` / `password` / `algorithm` 均为 `static` | `EncryptUtil.java:37,47,48` | 多商户证书串用，须**按商户隔离 + 缓存** |
| 4 | 每次签名都 `JCrypto.initialize(...)` | `EncryptUtil.java:81,121` | 性能差、线程安全存疑，须**单例初始化一次** |

## 8. 五大功能落点

| 功能 | 入口 | 实现 | 渠道接口 |
| --- | --- | --- | --- |
| 支付 | `POST /api/pay/unifiedOrder`（wayCode=`HCCB_QR`） | `HccbPaymentService` → `payway/HccbQr` | `1000/100010` |
| 退款 | `POST /api/refund/refundOrder` | `HccbRefundService.refund()` | `1008/100800` |
| 查询 | 商户侧 `/api/pay/query`（本地库）；渠道侧由轮询触发 | `HccbPayOrderQueryService.query()` | `1009/100900` |
| 异步通知 | `POST /api/pay/notify/hccb` | `HccbChannelNoticeService.doNotice()` | 返回 `success` |
| 轮询 | `PayOrderReissueTask`（cron 每分钟） | **复用现有任务，零新增** | 同查询 |

### 出码方式

支付成功后取 `txnTokenPayData.tokenCodeURL`：

- 默认放 `codeUrl`（前端自行生成二维码）
- `PAY_DATA_TYPE.CODE_IMG_URL` 时走 `sysConfigService.getDBApplicationConfig().genScanImgUrl(url)`

### 轮询

现有 `PayOrderReissueTask`（`task/PayOrderReissueTask.java:48`）每分钟扫 `state=ING` 且 `created_at <= now-10min` 的订单 → `ChannelOrderReissueService.processPayOrder()` → `getBean(ifCode + "PayOrderQueryService")`（`ChannelOrderReissueService.java:56`）。

**只要实现 `HccbPayOrderQueryService.query()` 并正确解析 `orderStat`，轮询自动生效。** 退款轮询同理走 `RefundOrderReissueTask`。

> 银行侧**只在支付成功时才通知 `backEndUrl`**，失败/关单不通知。因此**轮询是必需的补偿手段**，不是可选项。

**关键确认**：`orderStat=01` 对应「付过款、已退货」。`HccbPayOrderQueryService` 将 `00`/`01` 一并视为支付成功，判定正确。
